# Longform Agents

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE) [![Python 3.11](https://img.shields.io/badge/Python-3.11-blue.svg)]() [![CI](https://github.com/wyattzhangqian/longform-agents/actions/workflows/ci.yml/badge.svg)](https://github.com/wyattzhangqian/longform-agents/actions/workflows/ci.yml)

面向多模态长内容的多 Agent 协作框架。最底层，它是一套**高可靠的 Agent 协作框架**——让多个 AI 真正协作，把一件大而连续的事情做成；网文小说、漫画分镜、漫剧、歌曲，是它跑通的场景。

## 为什么会有它

单个 AI 做不了长内容。写小说，写一两章还行，往后角色开始漂、情节开始打架；画漫画，分镜和角色图对不上；做漫剧，剧情、画面、配乐各说各的。原因不复杂：一个模型没有"记得住前面、守得住一致"的能力，更别提同时管好文、图、声音几种形态。

Longform Agents 换了个思路：**别让一个 AI 硬扛，让一队分工的 AI 协作。**

Planner 把目标拆成阶段，每个阶段交给专门的 Agent——写手、编剧、分镜师、配乐，各有各的。这些 Agent 不是接力棒式的交接，而是能真商量：写手拿不准就直接问编辑，分镜师要参照上文的设定，关键内容写进一本台账，谁都不许改丢。领域规则和骨架再把一致性钉死，阶段产出不达标就重做，宁可显式失败也不假装成功。

## 它到底是什么

核心是一套**高可靠的多 Agent 协作框架**。可靠性体现在几个地方：

- Agent 之间能互相提问、拿同伴的结果继续做，不是各写各的
- 跨阶段的约束被提取、记账、注入、校验，前面埋的伏笔后面不会忘
- 阶段按依赖编排，能并行就并行，出问题能断点恢复，不半途而废
- 领域规则、骨架、质量校验把"一致"这件事制度化，而不是靠运气

这套框架本身不挑场景。它先跑通了多模态长内容——因为那是最能证明它价值的地方：一部漫剧要从文字到画面到声音全程对得上，靠的就是这套协作的可靠性。

## 能做什么

### 网文、小说、剧本

Planner 拆出大纲、初稿、润色、审校，专门的写手 Agent 负责各阶段，长内容骨架锚定全书设定，越写越不跑偏。

### 漫画分镜、角色图

漫画的分镜、角色参考图、线稿上色。生图 Agent 按剧本产出，质量规则检查构图和一致性。

### 漫剧

漫剧的配音脚本、分镜、后期。文字、画面、时间线由不同 Agent 协作推进，前后对得上。

### 歌曲、配乐

作词、作曲、编曲、混音、母带。音乐 Agent 按设定产出，规则校验节奏和情感走向。

四类内容不是孤立做的。一个项目里，写手、画师、配乐的 Agent 共用同一本**协商台账**（跨阶段约束不丢）和同一套**项目级骨架**（世界设定前后一致），但各自的**领域规则各有一套**——漫画审构图、音乐审节奏，规则跟着领域走。共享的是这套协作框架和规则机制，不是规则内容本身。

## 核心机制

### Planner：一句话变成可执行计划

意图识别、按领域套用标准流程、拆成带依赖的阶段。计划生成后自动检查步骤遗漏、依赖错误、该并行的没并行，发现问题自己改。想改计划，用自然话说就行："把调研和竞品分析并行"，它按你的意图重排，而不是推倒重来。

### 多 Agent 协作：真的商量，不是交接

`ask_peer` 让 Agent 在执行中真正调用同伴。协商闭环把跨阶段约束提取出来、注入下游、校验覆盖率、回写台账。运行中你也能插话干预。

### 工作流图执行引擎

阶段是图的节点，依赖是边，互不依赖的阶段并行跑。支持串行、并行、DAG。每个 Agent 用「模型 / 工具 / 技能」三维度配置。内建规则校验、断点恢复、运行锁。

### 领域知识与规则：一致性的 know-how

每个领域（网文、漫画、漫剧、音乐）的标准流程、质量规则、阶段骨架都是数据，存在 DB 里。扩展一个新领域不用改一行代码。这些规则是"一致性做到 90% 还是 60%"的差别所在，也是最值钱、不轻易公开的部分。

### 长内容骨架

骨架系统把整部作品**已定下来的设定**（人物、世界观、伏笔）和**每一章要写什么**记在案。Agent 动笔时自动带着这些上下文——写第几章都记得前面发生过什么，不会跟前文打架。这是长内容一致性在结构上的保障。

## 开源边界

本仓库是 Longform Agents 的开源引擎层，主框架全在这里：协作、规划、执行、骨架、领域规则体系。没公开的是平台产品层的细节——完整 Web 控制台、产品体验优化，以及各领域完整的知识规则与内容数据。后者随平台产品层维护，是"把一件事做到多好"的沉淀。

Alpha 阶段，API 与数据模型仍在演进。

## 快速开始

```bash
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env        # 填入 DEEPSEEK_API_KEY

# 跑一个 demo：自然语言 → 领域识别 → 计划分解 → Agent 匹配
.venv/bin/python examples/run_demo.py

# 跑引擎测试
.venv/bin/python -m pytest tests/ -x -q
```

想看整体结构，读 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。接入自己的应用，从 `core/orchestration/planner.py`（规划入口）和 `core/graph/runtime.py`（工作流图执行）入手。

## 安全说明

默认不启用认证，只适合本机或受信环境。生产部署前必须启用认证（`AUTH_ENABLED=true`）、配置独立密钥、限制 CORS、隔离工具执行环境。Shell 沙箱是尽力而为的防护，不是安全边界。
